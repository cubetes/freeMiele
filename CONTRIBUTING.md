# Contributing to freeMiele

Thanks for helping. freeMiele is an unofficial, community project: it is not made or endorsed
by Miele.

## Where the work is

- **Roadmap and what's being worked on:** the [freeMiele project board](https://github.com/users/cubetes/projects/2).
- **Issues:** pick one labelled `good first issue` or `help wanted`, and say in a comment that
  you're taking it.
- **No appliance to test with?** Many issues (docs, design, tests on sample data) don't need one.
- **Have a Miele appliance we don't know yet?** Open an "Appliance support report". It's the most
  useful contribution there is.

## Set up

1. Install Rust (stable).
2. Register your own client ID and secret at <https://developer.miele.com>. Every person needs
   their own; never share them. Self-registered keys are for personal, non-commercial use.
3. `cargo run -p freemiele-cli -- login`, then `cargo run -p freemiele-cli -- status`.

The code is a Cargo workspace: `crates/core` (package `freemiele`) talks to Miele, and
`crates/cli` (package `freemiele-cli`) is the `miele` command. Test fixtures live in `fixtures/`.

## Rules

- **No secrets or serial numbers in git.** Not in code, tests, fixtures, issues or screenshots.
  Real API replies go in `fixtures/*.json` (git-ignored); shared samples go in
  `fixtures/*.sample.json` with serial numbers replaced by zeros.
- **Tests:** `cargo test` runs against the sample files, never the live API. New logic with a
  branch, a loop or a parser gets a small test.
- **Keep it lean:** the smallest change that fully solves the problem. No new dependency for a
  few lines of code.
- **Design:** use the freeMiele colours and type from [`design/`](design/). Never use Miele's
  logo, red or fonts.
- **Official APIs only:** no reverse-engineering of Miele's private app protocols. Features the
  API lacks get an issue labelled `blocked: miele-api`.
- **Don't copy Miele's documentation** into the repo. Link to <https://developer.miele.com>.
- **Starting appliances is real.** Never run commands that start, stop or power an appliance in
  tests or CI.

## Issues: how we keep them useful

- **Same problem or same model?** Add a 👍 reaction instead of a "me too" comment. Comment only
  with new details (a different model, a new error message).
- **Please don't ask "any update?".** Progress shows up in the issue and on the
  [board](https://github.com/users/cubetes/projects/2).
- **Questions** go to [Discussions](https://github.com/cubetes/freeMiele/discussions); issues are for
  concrete work.
- **Triage:** a clear, reproducible issue gets labels and a priority. An unclear one gets one
  question and the `waiting for reporter` label; it closes by itself after 21 days without a
  reply, and reopens whenever you answer.
- **Priorities:** `P1` = planned for the current milestone; `P3` = welcome, not planned (a good
  pick for contributors). Anything that could start an appliance unasked or leak a login is fixed
  first: report those privately (see [SECURITY.md](SECURITY.md)).

## AI-assisted contributions

Using AI tools is fine; this project uses them too. What matters is behaviour:

- Only submit code you understand and can explain in review.
- Write issue and PR descriptions yourself, briefly; don't paste generated text in place of a
  discussion.
- Never claim something was tested or changed if it wasn't.

## Conduct

Everyone here follows the [Code of Conduct](CODE_OF_CONDUCT.md).

## Releases and versions

- **Version numbers:** major (`X.0.0`) for big new functionality, minor (`0.X.0`) for improving
  what exists, patch (`0.0.X`) for fixes and small comforts.
- **Code names:** each milestone release takes the next element of the periodic table:
  Hydrogen 0.1, Helium 0.2, Lithium 0.3, Beryllium 0.4, Boron 0.5, Carbon 1.0, Nitrogen next.
  Patch releases keep their parent's name ("Helium 0.2.1").
- **Release notes** are generated by GitHub from pull-request titles, so write titles a user
  understands ("Show descaling counter in status", not "fix fl parsing").
- One milestone a month, due on the 11th. See the [milestones](https://github.com/cubetes/freeMiele/milestones).

## Design

The look lives in [`design/`](design/): `tokens.json` (colours, fonts, spacing) and the brand
rules. Apps read the tokens file directly.
